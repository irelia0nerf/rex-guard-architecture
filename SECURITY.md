# Security and sensitive-disclosure policy

## Scope

This repository contains public architecture documentation. It is not a hosted
transaction service, operational security endpoint, or authorization to test a
production system.

Only the current default-branch documentation is maintained in this repository.
This policy creates no response-time SLA, bounty, legal safe harbor, or permission
to access any system beyond rights independently granted to you.

## Reporting

For a sensitive concern, use **Security → Advisories → Report a vulnerability**
if GitHub private vulnerability reporting is enabled for this repository.

If that private option is unavailable, open an issue containing only a request
for a private security contact. Do not disclose the vulnerability, affected
private asset, exploit instructions, credentials, logs, or personal information
in that public request. Wait for an appropriate private channel before sharing
sensitive details.

Non-sensitive documentation corrections belong in ordinary issues.

## Report contents

In a verified private channel, provide the affected document/version, a concise
description, impact, assumptions, and minimal supporting evidence you are
authorized to share. Use synthetic examples and redact secrets and personal data.

Do not test private repositories, customer environments, accounts, live targets,
or production endpoints on the basis of this document. Publication of an
architecture is not consent to scanning or exploitation.
